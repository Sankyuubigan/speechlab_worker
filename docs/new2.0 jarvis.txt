

Захват звука с эхоподавлением: Системный WASAPI (режим Communications) на чистом Rust — вырезает звук динамиков на уровне драйвера Windows без нагрузки на CPU и без C++ зависимостей.
Аудио-фасад (VAD + STT + TTS): CrispASR (встроенный Silero VAD для фиксации речи пользователя + SenseVoice для распознавания + Kokoro для синтеза).
Мозги (LLM): Отдельный независимый процесс llama-server.exe (по правилу §6.7, Qwen 2.5 7B, флаг CREATE_NO_WINDOW по §6.8).
Связка и фоновые задачи: Асинхронный Rust (tokio + CancellationToken для мгновенного Barge-in при срабатывании VAD).

Задействовать системный AEC операционной системы (Zero-overhead)
Если не хочется линковать C++ библиотеки WebRTC, можно заставить саму ОС вычитать звук колонок на уровне звукового драйвера:
На Windows (WASAPI Voice Capture):
Когда в Rust настраиваешь микрофон через cpal или windows-rs, нужно открыть аудиосессию с флагом категории AudioCategory_Communications и параметром CommunicationsStreams. Windows 10/11 автоматически активирует встроенный DSP-фильтр эхоподавления звуковой карты.
На macOS (CoreAudio VoiceProcessingIO):
В macOS встроен эталонный аппаратный AEC. Если открыть микрофон через подтип kAudioOutputUnitSubType_VoiceProcessingIO, macOS на уровне ядра начисто вырезает звук динамиков MacBook / колонок из микрофона.
Итоговый алгоритм для твоей связки:
TTS (CrispASR Kokoro) генерирует кусок аудио.
Этот кусок отдается в колонки и параллельно регистрируется в AEC (WebRTC / Sonora) как эхо[3].
Микрофон ловит звук из комнаты и прогоняет через AEC, который подчистую удаляет голос бота[1][3].
Очищенный сигнал идет в Silero VAD (CrispASR)[1][2].
Если VAD срабатывает, пока бот говорит — это 100% твой голос:
Срабатывает CancellationToken.
Плеер динамиков сбрасывает буфер (sink.stop()).
Очищенный голос идет в SenseVoice STT, распознается и летит в Qwen 2.5 (llama.cpp).


Системный AEC от операционной системы (WASAPI на Windows / VoiceProcessingIO на Mac)
Ты перекладываешь задачу на звуковую подсистему Windows/macOS.
👍 Плюсы:
Идеальная синхронизация таймингов «из коробки»: драйвер операционной системы точно знает, в какую миллисекунду звук вышел из ЦАП колонок и зашел в АЦП микрофона. Эхо гасится почти идеально без возни с буферами в коде.
Легкая сборка в Rust: не нужно компилировать тяжелый C++ WebRTC. Ты просто открываешь поток микрофона через стандартные API (windows-rs для Windows или coreaudio-rs для Mac).
Нулевая нагрузка на процессор: на macOS и многих современных ноутбуках на Windows эхоподавление считается аппаратно на встроенном аудио-чипе (DSP).
👎 Минусы:
Разный код под каждую ОС: код инициализации микрофона под Windows (WASAPI) вообще не имеет ничего общего с macOS (CoreAudio).
Проблемы с Linux: в чистом Linux системного AEC для каждого приложения по умолчанию нет. Придется надеяться, что у пользователя в PipeWire/PulseAudio включен модуль module-echo-cancel.
Побочные эффекты Windows («Режим связи»): когда ты открываешь микрофон в режиме Communications, Windows по умолчанию может приглушать (ducking) все остальные звуки на компьютере (игры, YouTube) на 80%, пока работает приложение (хотя это можно отключить в настройках системы).
Зависимость от кривых драйверов звуковой карты: если у пользователя на Windows стоит плохой драйвер от Realtek, системный шумодав может сделать голос глухим и металлическим.

### 2. Стек моделей под твою задачу (всё локально)

В связке **CrispASR + llama.cpp** берешь следующий набор:

1. **VAD (детектор речи) — берем из CrispASR:**
   * В CrispASR уже **встроен Silero VAD** (а также `FireRedVAD` и `MarbleNet` с поддержкой русского). Тебе не нужно искать сторонние библиотеки.
2. **STT («Уши») — берем из CrispASR:**
   * Модель **`sensevoice`** (или `whisper-turbo` / `parakeet-tdt`). Для русского языка `sensevoice` выдает транскрипт за ~30–50 мс, не жрет видеопамять.
3. **LLM («Мозги и логика задач») — берем в `llama.cpp`:**
   * Модель **`Qwen 2.5 7B Instruct`** (GGUF Q4_K_M). Она идеально знает русский и нативно поддерживает Tool/Function Calling (то есть умеет подать команду: `run_background_task(...)`).
4. **TTS («Голос») — берем из CrispASR:**
   * Модель **`kokoro`** (или `piper`). Очень быстрая, генерирует звук чанками почти мгновенно.

### 4. Архитектура приложения в Tauri (Rust) с Barge-in

В Tauri бэкенд на Rust управляет аудио и задачами через каналы.

```text
       [ Микрофон (cpal) ]
               │ (PCM поток)
               ▼
       [ CrispASR (Silero VAD) ] ──(тишина)──> спим
               │ (голос обнаружен)
               ├──> [ Если TTS говорил -> ОТМЕНА (Barge-in)! ]
               ▼
       [ CrispASR (SenseVoice STT) ]
               │ (текст: "поставь задачу...")
               ▼
       [ llama.cpp (Qwen 2.5) ]
        ├── Ответ в чат ──> [ CrispASR (Kokoro TTS) ] ──> [ Динамики ]
        └── Tool Call  ──> [ tokio::spawn(фоновая работа) ]
                                    │ (задача выполнена)
                                    └──> [ Event в диалог ]
```

#### Как реализуется Barge-in (перебивание) на Rust:

Для перебивания используется **`tokio_util::sync::CancellationToken`**.

1. **Пока ассистент говорит:**
   * Генерация TTS и отправка аудио в динамики (через крейт `rodio` или `cpal`) привязаны к токену: `playback_token`.
2. **Параллельно микрофон слушает всегда:**
   * Звук с микрофона чанками по 20–30 мс скармливается во встроенный **Silero VAD** из CrispASR.
3. **Момент перебивания:**
   * Пользователь начинает говорить поверх ответа бота.
   * VAD возвращает вероятность речи > 0.8 на протяжении хотя бы 100–150 мс.
   * **Rust немедленно делает:**
     1. `playback_token.cancel()` — останавливает воспроизведение звука в динамиках и очищает аудио-буфер плеера.
     2. Обрывает текущую генерацию в `llama.cpp` и `CrispASR TTS`.
     3. Начинает накапливать входящий звук в буфер, пока VAD не зафиксирует конец реплики (паузу в 500 мс).
     4. Передает буфер в `CrispASR (SenseVoice)` на распознавание.

*(Важный момент: чтобы бот не перебивал сам себя звуком из динамиков, используй гарнитуру/наушники либо программное эхоподавление).*

### 5. Как устроена фоновая работа и уведомления

1. Пользователь говорит: *«Спарси мне цены с сайта X»*.
2. STT отдает текст в `llama.cpp`.
3. `Qwen 2.5` выдает структурированный вызов инструмента (JSON):
   ```json
   {"tool": "scrape_prices", "target": "site_x"}
   ```
   И одновременно генерирует короткую голосовую реплику для пользователя:
   *«Принял, пошел собирать данные, пока займет пару минут...»* (это сразу улетает в CrispASR TTS и озвучивается).
4. Rust перехватывает `tool_call` и запускает задачу в фоне:
   ```rust
   tokio::spawn(async move {
       let result = do_heavy_scraping().await;
       // Задача завершилась — шлем сигнал в диалог
       event_sender.send(BotEvent::TaskFinished(result)).await;
   });
   ```
5. Когда фоновая задача завершилась:
   * Rust перехватывает `TaskFinished`.
   * Отправляет в контекст `llama.cpp` системное сообщение: `[Система: Задача "парсинг цен" завершена. Результат: найдено 5 товаров. Уведоми пользователя.]`.
   * `llama.cpp` генерирует: *«Кстати, я закончил сбор цен — вот что нашлось...»*.
   * CrispASR (Kokoro) синтезирует аудио и проигрывает пользователю.
